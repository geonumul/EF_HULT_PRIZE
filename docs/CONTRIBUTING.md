# 작업 규칙

## 브랜치

- `main`: 배포되는 브랜치. 직접 푸시하지 않고 `dev`에서 합친다.
- `dev`: 통합 브랜치.
- `feat/<이름>`, `fix/<이름>`: 작업 브랜치. 끝나면 `dev`로 합친다.

## 커밋 메시지

`<종류>: <한 줄 설명>` 형식으로 쓴다. 종류는 `feat`, `fix`, `docs`, `style`, `refactor`, `chore` 중에서 고른다. 설명은 한국어로 쓰고 무엇을 바꿨는지만 적는다.

```
feat: 공실 지도 화면 추가
fix: 견적 합계가 중고 선택 때 갱신되지 않는 문제 수정
docs: 배포 환경변수 표 추가
```

## 올리면 안 되는 것

- `.env` 파일, API 키, 서비스 계정 JSON
- 공모전 제출 서류(`.hwp`)와 개인 연락처가 든 파일
- 개발 도구의 설정 파일과 작업 기록

`.gitignore`에 이미 들어 있다. 커밋 전에 `git status`로 한 번 확인한다.

## 주석과 문서

- 주석은 코드가 왜 그렇게 되어 있는지만 적는다. 코드를 읽으면 알 수 있는 내용은 적지 않는다.
- 파일 맨 위에 한 줄로 역할을 적는다. Figma에서 가져온 화면이면 프레임 ID를 같이 적는다.
- 문서는 결론을 먼저 쓴다. 수치와 파일 경로는 실제 값을 쓴다.
