# 데이터 수집과 AI 학습 계획

이 서비스에 필요한 데이터는 네 가지다. 어느 공간이 비어 있는가, 그 공간의 건물 정보, 가구와 설비 상품, 시공과 철거 가격이다. AI는 다섯 곳에 쓰이는데, 처음에는 학습 없이 만들고 데이터가 쌓인 뒤에 학습으로 넘어간다.

## 1. 공실과 매물 데이터

### 정리

가장 믿을 만한 출처는 중개사와 임대인이 직접 등록한 매물이다. 공공 데이터는 "비어 있을 가능성이 높은 곳"을 찾는 후보 목록으로 쓴다. 매물 중개 앱(네이버 부동산, 직방, 다방 등)의 화면을 긁어 오는 방식은 쓰지 않는다. 약관 위반과 부정경쟁 분쟁의 위험이 있다.

### 출처

| 출처 | 얻는 것 | 용도 |
|---|---|---|
| 파트너 콘솔(S10) 직접 등록 | 주소, 면적, 층, 보증금, 월세, 사진 | 매물의 기본 데이터. 이미 화면이 있다 |
| 한국부동산원 상업용부동산 임대동향조사 (R-ONE) | 지역별 공실률 | 지역 단위 통계 표시, 시장 현황 |
| 건축HUB 건축물대장 (공공데이터포털) | 층별 용도, 면적, 사용승인일 | 업종 적합성 진단, 건물 확인 |
| 소상공인시장진흥공단 상가(상권)정보 | 영업 중인 점포와 층 | 층에 영업 점포가 없으면 공실 후보 |
| 지방행정 인허가 데이터 (LOCALDATA) | 영업 상태, 폐업일 | 최근 폐업한 자리는 공실 후보 |
| 서울 열린데이터광장 상권분석 | 점포 개업과 폐업 수 | 상권 단위 회전율 |
| 온비드, LH, SH 상가 공고 | 공매와 공공임대 상가 | 공공이 공개하는 매물. 합법적으로 쓸 수 있다 |
| 이용자 제보 | 임대 현수막 사진과 위치 | 현장 확인용 |

각 서비스의 호출 방식과 응답 필드는 사용하기 전에 공식 문서로 확인한다.

### 공실 후보를 찾는 규칙

1. 건축물대장에서 상가 용도(근린생활시설 등)가 있는 층의 목록을 만든다.
2. 상가정보에서 같은 주소와 층에 영업 중인 점포가 있는지 확인한다.
3. 영업 점포가 없거나, 인허가 데이터에서 최근 6개월 안에 폐업한 점포가 마지막이면 "공실 후보"로 표시한다.
4. 후보는 화면에 "확인 전"으로 보여 주고, 중개사 확인이나 사진이 붙으면 "확인됨"으로 바꾼다.

이 규칙은 추정이다. 틀리는 경우가 많으므로 확인 절차가 필요하다. 후보 100곳을 중개사가 확인해서 실제 공실 비율(정밀도)을 재고, 낮으면 규칙을 고친다.

### 첫 6주 계획

| 주 | 할 일 |
|---|---|
| 1~2 | 성수동과 대학가 중개사 5곳을 만나 파트너 콘솔로 매물 20건을 직접 등록받는다 |
| 2~3 | 건축HUB, 상가정보, 인허가 데이터를 받아 두 동네의 공실 후보를 만든다 |
| 3~4 | 후보를 현장에서 50곳 확인해 정밀도를 측정한다 |
| 5~6 | 확인된 곳에 사진을 붙여 지도에 "확인됨"으로 올린다 |

## 2. 상품과 가격 데이터

| 출처 | 방식 |
|---|---|
| 네이버 쇼핑 검색 API | 카테고리 키워드로 매일 수집. 이름, 최저가, 판매처, 이미지, 링크 |
| 쿠팡 파트너스 API | 상품 검색과 제휴 링크 |
| 입점 공급사 | CSV 일괄 등록(S10에 구현됨), 판매처 링크 |
| 폐업 매장 중고 | 점주가 사진 3장과 상태 등급을 올린다 |

- 치수(W·D·H)는 렌더링 배치에 꼭 필요하다. 상품명과 상세에서 추출하고, 없으면 공급사가 입력해야 등록된다.
- 시공과 철거 단가는 공개 기준이 없다. 업체 2~3곳에서 받은 단가표로 시작하고, 견적이 쌓이면 실제 낙찰 금액으로 보정한다.

## 3. AI를 쓰는 곳과 학습 계획

| 기능 | 처음 방식 | 학습이 필요한 시점과 방법 |
|---|---|---|
| 업종 적합성 판정 | 규칙표(AI 아님). 법과 시공 기준을 전문가가 검수 | 학습하지 않는다. 틀리면 안 되는 부분이라 규칙으로 둔다. 건축물대장 문구를 읽는 보조로만 LLM을 쓴다 |
| 텍스트 요청 해석 (S04) | 상용 LLM API. 요청을 배치 조건(업종, 좌석 수, 스타일)으로 바꾼다 | 학습하지 않는다. 지시문과 예시로 고정하고, 요청 50개의 정답표로 정확도를 잰다 |
| 공간 렌더링 | 상용 이미지 생성 API에 사진과 깊이, 구조 조건을 넣는다 | 스타일이 일정하지 않을 때만 스타일별 LoRA를 학습한다. 라이선스가 있는 인테리어 사진 스타일당 100~200장이 필요하다 |
| 상품 매칭 | CLIP 임베딩과 벡터 검색. 학습 없음 | 이용자가 "비슷한 상품"에서 다른 상품으로 교체하는 기록이 정답 쌍이다. 1,000쌍이 모이면 임베딩 모델을 미세 조정한다 |
| 비용 예측 | 단가표와 규칙 | 실제 견적이 200건 이상 쌓이면 면적, 업종, 건물 연식으로 회귀 모델을 학습해 규칙과 비교한다 |

학습 데이터를 모으는 방법은 서비스 안에 넣는다. 이용자가 상품을 교체하거나 견적을 수정하면 그 기록(렌더링에서 잘라낸 이미지, 고른 상품, 수정 금액)을 저장한다. 이 기록이 상품 매칭과 비용 예측의 학습 데이터가 된다. 이용자에게 이 사실을 알리고 동의를 받는다.

### 처음 학습 없이 시작하는 이유

학습에는 데이터가 필요하고, 데이터는 서비스가 쓰여야 쌓인다. 처음부터 모델을 학습하면 데이터가 없어서 상용 모델보다 나쁘다. 그래서 상용 API로 시작하고, 이용자 기록을 쌓아 정확도가 부족한 곳만 학습으로 바꾼다.

### 평가 기준

| 기능 | 기준 |
|---|---|
| 상품 매칭 | 상위 3개 안에 정답이 있는 비율 80% 이상 |
| 텍스트 요청 해석 | 요청 50개 중 배치 조건을 맞게 뽑은 비율 90% 이상 |
| 치수 검증 | 규칙 위반을 놓친 건수 0 |
| 공실 후보 | 후보 중 실제 공실 비율(정밀도) 측정, 목표는 첫 측정 후 정한다 |

기준 수치는 시작점이다. 첫 측정 결과를 보고 조정한다.

## 4. 법과 권리

- **사진 저작권.** 학습에 쓰는 인테리어 사진은 직접 찍었거나 이용 허락을 받은 것만 쓴다. 검색해서 받은 이미지는 쓰지 않는다.
- **개인정보.** 현장 사진에 사람 얼굴과 연락처가 있으면 지우고 저장한다. 임대 현수막의 전화번호는 저장하지 않는다.
- **크롤링.** 약관이 금지하는 사이트는 긁지 않는다. 공공데이터포털의 이용 조건을 따른다.
- **제휴 링크.** 수수료를 받는 링크는 화면에 고지한다(이미 푸터에 문구가 있다).
- **AI 결과 표시.** 렌더링은 이미지이고 실제 시공 결과와 다를 수 있다고 화면에 표시한다. 업종 판정은 참고 정보이며 계약 전 관할 기관 확인이 필요하다고 표시한다.
