# 실제 데이터 계획

시연에 쓰는 공실을 실제 성수동 상가로 채운다. 렌더링 이미지만 사전 생성한 결과를 쓰고, 나머지는 현장 사진과 공공 데이터로 채운다.

## 목표

- 실제 공실 3~5곳(카페 후보, 팝업 후보, 필라테스 후보가 하나씩 포함되게 고른다)
- 곳마다 현장 사진 3~6장, 실측 치수, 건축물대장 정보, 주변 점포 현황
- 곳마다 업종 3개의 사전 생성 렌더링과 견적서

## 역할

| 담당 | 할 일 |
|---|---|
| 이인영 | 현장 촬영과 간이 실측, 공실 후보 방문 |
| 서영아 | 업종별 배치 기준 검수, 렌더링 결과 확인 |
| 김예지 | 집기 상품 정보 수집과 정리 |
| 고건 | 데이터 수집 코드, 등록, 렌더링 생성, 화면 연결 |

## 현장 수집 체크리스트

곳마다 아래를 모은다. 사진 속 사람 얼굴과 임대 현수막의 전화번호는 가리거나 지운다.

1. 지번 주소와 층, 상호가 있던 자리면 이전 업종
2. 사진: 외관 1장, 내부 전경 2장(입구에서 안쪽, 안쪽에서 입구), 천장과 바닥 각 1장, 창과 출입문 1장
3. 실측: 가로, 세로, 천장 높이(m), 출입문 폭, 기둥 위치
4. 임대 조건: 보증금, 월세, 관리비, 권리금 (중개사에게 확인)
5. 설비 상태: 화장실, 급배수, 환기구, 전기 용량 표시(분전반 사진)
6. 중개사 이름과 연락처 (등록 허락을 받은 경우만)

## 처리 순서

1. 지번 주소를 카카오 로컬로 바꿔 좌표와 법정동 코드를 얻는다. 카카오 REST 키는 연결되어 있고 실제 응답을 확인했다.
2. 건축HUB 건축물대장에서 주용도, 층별 용도, 면적, 사용승인일을 읽는다.
3. 브이월드에서 용도지역을 읽는다.
4. 상가정보에서 반경 300m 점포와 같은 건물 점포를 읽는다.
5. 업종 적합성 규칙으로 판정하고 근거를 저장한다.
6. 매물을 `listings`와 `spaces`에 "확인됨" 상태로 등록하고 사진을 Supabase Storage에 올린다.
7. 상품 DB에서 업종별 집기를 고르고 실제 치수로 배치한다.
8. 이미지 생성 API로 업종별 렌더링을 만들어 저장한다. 결과가 마음에 들 때까지 곳마다 여러 번 만들고 가장 좋은 것을 쓴다.
9. 렌더링 속 집기를 상품과 연결하고 견적서를 만든다.
10. 시연 순서대로 화면을 돌려 보며 영상으로 녹화한다.

## 준비 순서와 기한

| 단계 | 할 일 | 기한 |
|---|---|---|
| 1 | 공공데이터포털, 브이월드, 네이버 키 신청 | 오늘 |
| 2 | 성수동 공실 후보 8곳을 둘러보고 5곳을 고른다 | 3일 안 |
| 3 | 5곳 현장 촬영과 실측 | 5일 안 |
| 4 | 주소로 건물과 점포 정보를 읽어 등록 | 키를 받은 뒤 2일 |
| 5 | 사전 렌더링 생성과 견적 확인 | 등록 뒤 3일 |
| 6 | 시연 영상 녹화 | 마지막 |

## 정할 일

- 이미지 생성 API로 무엇을 쓸지. 한 번에 한 곳씩 시험해 보고 고른다.
- 임대 안내문이나 중개사 연락처를 화면에 보여도 되는지 중개사에게 허락을 받는다.
- 발표에서 "렌더링은 사전 생성 결과, 판정과 견적은 규칙 기반"이라고 밝힌다.
