# 개발 단계

한 단계가 끝나면 커밋하고 이 표의 상태를 바꾼다.

| 단계 | 내용 | 상태 |
|---|---|---|
| 1 | 저장소 뼈대, 배포 구조 문서, 디자인 토큰 CSS | 완료 |
| 2 | Next.js 앱 생성, 공통 레이아웃(Header, Footer) | 완료 |
| 3 | S01·S02 공실 지도 화면. 카카오맵(키 없으면 정적 지도), 가짜 데이터 | 완료 |
| 4 | Supabase 스키마와 시드 적용, `backend/` API(인메모리와 Postgres 두 방식) | 완료. 지도, 견적 목록, 마켓은 연결됨 |
| 5 | S03 공간 스튜디오, S04 텍스트 렌더링 화면. 렌더링 방식 선택(이미지 먼저 / 상품 먼저) 포함 | 화면 완료, 가짜 데이터 |
| 6 | Firebase 렌더링 작업(`text`, `products` 두 방식), 상품 매칭, 견적 계산 | 함수 3개 배포 완료. 외부 서비스는 가짜 구현 |
| 7 | S05 견적 확정, S06 결제 완료. 토스페이먼츠 연결 | 화면 완료, 키 없으면 데모 결제 |
| 8 | S07 집기 마켓(렌더링 보드 담기 포함), S08 창업 가이드, S09 로그인, S10 파트너 콘솔, S11 입점 문의 | 화면 완료, 로그인은 키가 있으면 Supabase |
| 9 | 철거 견적 추정, 철거 업체 매칭(요청, 견적 비교, 선택, 후기). [FEATURES.md](FEATURES.md) 참고 | 화면 완료, 가짜 데이터. 확정 철거비는 견적서에 반영됨 |

| 10 | 공실 등록 도구, 공실 후보 탐색과 지도 표시. [REAL_DATA_PLAN.md](REAL_DATA_PLAN.md) 참고 | 도구 완료. 후보 탐색 결과를 지도에 표시하는 중 |

## 다음 할 일

1. 스튜디오, 견적서, 철거, 결제 화면을 백엔드 API로 연결한다.
2. 성수동 공실 3~5곳을 촬영해 등록 도구로 올린다.
3. 후보 100곳을 현장에서 확인해 판정 규칙의 정밀도를 잰다.
4. 이미지 생성 API를 고르고 시연용 렌더링을 만든다.
5. 철거 단가표와 설비, 시공 단가표를 업체에서 받아 예시 단가를 바꾼다.
