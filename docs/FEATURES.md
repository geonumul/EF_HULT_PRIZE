# 추가 기능 설계

Figma 시안에 없는 기능 두 가지를 정리한다. 시안에 화면이 없어서 만들기 전에 정할 일이 하나 있다. Figma에서 화면을 먼저 그릴지, 기존 토큰과 컴포넌트를 따라 코드로 바로 만들지다. 이 문서는 후자를 기준으로 개발 단계를 잡았다.

## 1. 렌더링 방식 두 가지

| 방식 | 순서 | 화면 |
|---|---|---|
| A. 이미지 먼저 | 텍스트로 요청 → 이미지 생성 → 이미지 속 집기 검출 → 비슷한 상품 찾기 → 판매처 링크와 견적 | S04 (시안 있음) |
| B. 상품 먼저 | 마켓에서 상품 고르기 → 고른 상품만으로 배치와 이미지 생성 → 태그마다 상품 링크 → 견적 | S07 집기 마켓과 S03 (B 흐름은 시안 없음) |

### B 방식 흐름

1. 사용자가 집기 마켓에서 상품을 "렌더링 보드"에 담는다. 수량도 정한다.
2. 보드에서 "이 상품들로 렌더링" 버튼을 누른다.
3. `POST /render-jobs`에 `mode: "products"`와 상품 목록을 보낸다. 기존 A 방식은 `mode: "text"`다.
4. 배치 단계에서 고른 상품의 실제 치수(W·D·H)로 평면을 짠다. 통로 폭과 좌석 간격 검증은 기존 규칙을 그대로 쓴다.
5. 이미지 생성 단계에서 상품 이미지를 레퍼런스로 넣는다.
6. 결과 이미지의 태그 위치는 상품 id와 바로 연결된다. 검출과 유사도 매칭 단계가 필요 없다.
7. 견적은 A 방식과 같은 로직으로 계산한다.

공간에 들어가지 않는 상품이 있으면 치수 검증에서 어떤 상품이 문제인지 알려준다. 판매처 링크가 없는 상품은 마켓에서 담을 수 없다(Figma "09 API · 상품 연결"의 링크 규칙).

### 데이터 변경

| 테이블 | 변경 |
|---|---|
| `renders` | `mode` 열 추가. 값은 `text` 또는 `products` |
| `render_boards` (신규) | `id`, `user_id`, `space_id`, `use_type` |
| `render_board_items` (신규) | `board_id`, `product_id`, `qty` |

두 방식의 결과 모두 기존 `renders`와 `render_items`에 저장한다. 견적과 결제 화면은 방식을 구분하지 않는다.

## 2. 철거 견적과 업체 매칭

빈 공간이 아니라 기존 점포가 있는 곳은 철거비가 창업비에 들어간다. 철거비를 견적에 넣고, 철거 업체를 숨고처럼 요청 한 번으로 연결한다.

### 공간 상태

`spaces.condition` 열을 추가한다.

| 값 | 뜻 | 철거 |
|---|---|---|
| `vacant` | 빈 공간 | 없음 |
| `has_fixtures` | 집기나 마감이 일부 남아 있음 | 부분 철거 |
| `occupied` | 영업하던 점포 | 전체 철거 |

### 철거비 추정

철거 범위는 천장, 바닥, 벽체, 설비, 간판으로 나누고 폐기물 처리비를 더한다. 단가는 공개된 기준이 없다. 철거 업체 2~3곳에서 받은 실제 단가표로 규칙표를 만들고, 그 전에는 숫자를 넣지 않는다. 입력은 면적과 남은 시설이고, 결과는 하한과 상한 범위다.

### 업체 매칭 흐름

1. 사용자가 공간 사진, 면적, 남은 시설을 입력한다.
2. 시스템이 단가표 기준의 추정 범위를 보여준다.
3. 사용자가 "철거 견적 받기"를 누르면 요청이 만들어진다.
4. 같은 지역의 철거 파트너 최대 3곳에 요청이 전달된다.
5. 업체가 금액, 시작 가능일, 포함 범위를 입력해 견적을 보낸다.
6. 사용자가 견적을 비교하고 한 곳을 고른다.
7. 확정된 철거비가 견적서의 "철거" 그룹에 들어간다.
8. 작업이 끝나면 사용자가 후기를 남긴다.

수익은 시공 연결형과 같다. 계약이 성사되면 수수료를 받는다. 비율은 정하지 않았다(Figma의 시공 연결형은 3%).

### 데이터 변경

| 테이블 | 변경 |
|---|---|
| `spaces` | `condition` 열 추가 |
| `vendors` | `type`에 `demolition` 추가 |
| `demolition_requests` (신규) | `id`, `space_id`, `user_id`, `scope` (json), `status` |
| `demolition_bids` (신규) | `id`, `request_id`, `vendor_id`, `amount`, `start_date`, `scope_note`, `status` |
| `reviews` (신규) | `id`, `vendor_id`, `request_id`, `rating`, `body` |
| `quotes.breakdown` | `demolition` 그룹 추가 |

### API 추가

| 메서드 | 경로 | 설명 |
|---|---|---|
| POST | `/spaces/:id/demolition-estimate` | 철거비 추정 범위 |
| POST | `/demolition-requests` | 철거 견적 요청 |
| GET | `/demolition-requests/:id/bids` | 받은 견적 목록 |
| POST | `/demolition-requests/:id/accept` | 업체 선택 (`bid_id`) |
| GET | `/partner/demolition-requests` | 파트너가 받은 요청 |
| POST | `/partner/demolition-requests/:id/bids` | 파트너가 견적 제출 |

### 화면에 넣을 안내

철거에는 건물주 동의, 원상복구 범위, 폐기물 처리, 석면 확인이 걸려 있다. 서비스는 법적 판단을 하지 않고 "확인이 필요한 항목" 목록으로만 알려준다. 건축 연도가 오래된 건물은 석면 조사가 필요할 수 있다고 안내하고, 확정은 업체와 관할 기관에 맡긴다.

## 개발 단계에 넣는 위치

[ROADMAP.md](ROADMAP.md)에 반영했다.

- 5단계: 스튜디오 화면에 렌더링 방식 선택(이미지 먼저, 상품 먼저)을 넣는다.
- 6단계: `mode: "products"` 작업 처리를 만든다.
- 9단계: 철거 견적과 업체 매칭 전체.

## 정할 일

- 이 두 기능의 화면 시안을 Figma에서 먼저 그릴지, 기존 토큰으로 코드에서 바로 만들지.
- 철거 단가표를 받을 업체와 시기.
